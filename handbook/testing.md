### 7-A 每個階段都要做的測試

1. **自動測試**：規則引擎、計分、權限（RLS 用 PGlite、Firebase 規則用 targaryen）都要有測試；每次改完全部跑一遍（`npm test`、`node firebase/rules.test.js`），數字寫進 CHANGELOG。
2. **崩潰測試**：連點、網路很慢、斷線、重新整理、換裝置、舊資料／壞資料、奇怪的輸入（負數座號、超長文字、emoji、`<`）、手機／iPad／超寬螢幕。
3. **人數壓力測試**：以 50 人／50 組，模擬真實延遲（每次寫入 +0.2 秒）、隨機失敗（20～30%）、回應遺失；確認沒有重複、沒有遺漏（例：40 人同時發文按讚，重送 133 次後貼文 120／120、讚 40／40）。
4. **用「有資料」的狀態把每個分頁、彈窗、選單點開一次**（空資料時不會觸發的錯最容易漏）。
5. **用眼睛看截圖**：極短（1～3 字）、很長、空白、很多筆各看一次；手機 390／320、平板 820、桌機 1280／1920；不能只檢查文字存在。
6. 規則一定經過真正的規則檢查；網頁測試的假 Firebase 也用真規則。
7. **完整教學流程跑一次**：用 Playwright 從老師開課 → 學生手機操作 → 投影 → 公布 → 學生看結果，每一步截圖檢查。

### 7-B 攝影棚與截圖

- 截圖一律用**攝影棚**（`wuyutzu-tools/tools/studio/`）：本機假 Firebase＋把正式網址導到本機＋假 `fb.js`＋CDN 改本機套件；課堂小鎮用模擬模式（`npm run dev:mock`）。**完全不碰真正的 Firebase、Supabase**。
- 資料用網頁自己的程式產生（模擬全班上課）；限時遊戲用 `clock` 快轉；重拍同一位道具學生要先清紀錄。
- **假名字**：「姓氏＋大／小＋一個字」（`names.py`）；拍照前「名字濾鏡」把本名換成巫魚子、系統自己產生的虛構人名也換成同樣格式。
- **不能露出測試網址**：每個頁面加 init script，把畫面文字裡的 `localhost:埠號`／`127.0.0.1` 換成正式網址（MutationObserver 持續換）；共用 `tools/studio/classroom-town/studio-pre.cjs`（`node -r` 掛上去）。
- **新系統開放後也要拍截圖、產生分享頁**；說明頁用縮圖格子，不要一張張大圖往下排。
- 一鍵重拍：`run_all.sh`（Firebase 系統）、`run_grade.sh`（成績調閱室）→ `pack.py`（挑圖、壓縮 WebP、縮圖）。
- 攝影棚測試用固定的資料快照（`tools/studio/fixtures/`），新功能補一段測試（例：展覽館 `sc_admin.py`、`sc_stats.py`、`sc_mother.py`）。
- **要分享到社群的頁面不能靠 JavaScript 產生標題與內容**（LINE、Facebook 不執行 JS）→ 靜態 HTML＋og 標籤（og:image 用完整網址），產生時自動檢查「零連結」。
