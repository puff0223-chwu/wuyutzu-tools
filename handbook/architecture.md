### 4-C 選平台：Firebase 還是 Supabase？

> 一句話：**Firebase 給輕量小工具，Supabase 給大系統。** 兩邊資料與登入分開，靠伺服器（Vercel）溝通。

| 想做的系統… | 選 | 例子 |
|---|---|---|
| 課堂即時互動、搶答、排行榜、投影看板 | **Firebase**（事務所） | 遺落的地點、公告欄、鍵結社連線版 |
| 一個單元的練習／遊戲，資料結構簡單 | **Firebase**（事務所） | 化學 No.223 三系統、時光手稿 |
| 要分享給其他老師、走會員中心的小系統 | **Firebase**（事務所） | 線上檢定所、座位大作戰 |
| 要呼叫 AI（金鑰要藏在後端） | **Supabase＋Vercel**（或借 Vercel API） | 科普閱讀測驗、出處失傳的秘文借它的 API |
| 長期累積、要複雜篩選統計、很多「誰和誰有關」的資料 | **Supabase＋Vercel** | 課堂小鎮、科普閱讀測驗、偵探所 |
| 大型編輯器、素材庫、多關卡任務 | **Supabase＋Vercel** | 科學任務偵探所 |
| 完全不用存資料 | **都不用**（單一 HTML、存在瀏覽器） | 詩籤、金曲歌王、聖誕抽籤、課堂遊戲化三工具、化學尋寶 |

- 新的 Firebase 系統 → 放進 wuyutzu-tools，共用 Point-Collection Stash 專案與會員中心。
- 新的 Supabase 系統 → **先想能不能放進課堂小鎮**（同一個 repo、同一個 Vercel、同一個 Supabase，共用學生帳號、名單、老師登入；新表加前綴，例 `cc_`、`vc_`）。Supabase 免費方案一個帳號只能有 2 個專案，開新專案很貴。
- 真的要獨立 → 獨立 repo＋Vercel 專案；**完工就設 cron-job.org 保活**；首頁放一張外部連結卡。
- Firebase 系統只要用 AI，不用整個搬去 Supabase：借 Vercel 系統的 API。

### 4-D 會員中心與教師展覽館

**👥 會員中心** `account/`
- 老師自己申請（Google 或 Email 註冊）→ 管理員核准並勾選系統；也可手動新增（有 UID 直接開通、沒 UID 預先開通 `staffpre`，領取要信箱已驗證）。
- 權限記在 `staff/<uid>`（status＋apps，**apps 的值只能是 true**）；共用檔 `fb.js`（連線、登入、`FB.idle()`）、`staff.js`（`WuStaff.check()`、`APPS`、`SUITES`、`href()`、`isAdmin()`）。
- 課堂小鎮四個系統分成一組＋「☑ 整套申請」（`SUITES.town`）；`?app=grade,cc,exam` 一次勾好多個；`&back=<卡片>` 返回展覽館那一頁。
- 📧 **申請通知**：送出申請／加開後呼叫課堂小鎮的 `/api/teacher/notify`，用 Resend 寄信給管理員；每筆只寄一次（記在 `staffnote/<uid>`，網頁讀寫不到）；每天 08:00 排程補寄。
- 📊 **使用狀況**（管理員分頁）：Firebase 與 Supabase 用量燈號（🟢 50% 以下／🟡 50～80%／🔴 80% 以上）、成長曲線與「幾個月後到 80%」、每位老師每個系統建了多少＋最後使用日（`staffseen`）、篩選「核准了還沒用」「兩個月沒用」。盤點在課堂小鎮伺服器（同時拿得到兩個資料庫的鑰匙），寫進 `stats/summary`；每週一 02:00 自動。免費方案看不到的數字先留 null，升級後補上、畫面不用改。
- 已開通的外校老師：zoo@dssh、t059@m2.ymjh（請他們繼續用 Email＋密碼登入）。

**🏛️ 教師展覽館** `showcase/`
- 給其他老師看的對外展示站：外觀同事務所首頁，只展出老師開放的系統；卡片 → `guide.html?app=代號` 使用說明（左目錄＋說明卡）→ 申請（會員中心）或直接開啟。
- **老師自己管理**：`showcase/admin.html`（頁尾 🔧，只有管理員帳號），內容存 Firebase `showcase/pub`、`showcase/img`（大家能讀、只有管理員能寫）。
- 兩層展出設定：👁️ 看得見／🙈 看不見 → 👀 只展示／✅ 開放使用；開放使用時**系統自動判斷** 🔐 要申請（會員中心有這個系統）或 🚀 免申請直接用（沒有帳號系統的工具）。
- **跟著首頁走**：管理頁直接讀首頁的 `TOOLS`；每張卡片存一份首頁快照（`mref`），逐欄比對，改了什麼列在「📬 需要你看一下」；名稱、圖示、位置可以「🔗 跟首頁同步」，一句話只提醒不自動改；首頁新工具、首頁已刪的工具、會員中心有代號但展覽館沒卡片，都會提醒；籌備中的不提醒。
- **🏘️ 套組卡**：一張卡片包好幾個系統（課堂小鎮＝成績調閱室＋謎案課堂＋英勇學院＋線上檢定所），套組一個開關、成員各自的開關與開放方式；可「📝 一次申請」；成員可「📌 也單獨展出」。
- 健檢：⛔ 問題沒修好不能讓人看見；「🚀 免申請」的頁面不能有回事務所首頁的按鈕。
- 📤 **社群分享頁** `share/<代號>.html`：只看這一頁、**完全沒有連結**；靜態 HTML＋og 預覽圖（LINE、Facebook 不跑 JS）；GitHub Action 每 30 分鐘看 `rev`，有改才重做（產生器 `node showcase/tools/build_share.js`、預覽圖 `python3 showcase/tools/make_og.py`；原本的 `showcase/data.js`、`drafts.js` 現在只當初版內容與備援）。
- 讀取順序：Firebase 版本號（很小）→ 和 GitHub 快照一樣就用快照（省流量）→ 連不上用快照 → 這台裝置上次的資料 → 內建內容。

### 4-E WYTClass 課堂小鎮的結構

比喻：一座小鎮（WYTClass）＋四棟建築（四個系統）＋鎮公所發的**職員證**（會員中心開通）＋大家共用的**道路水電**（共用地基）＋大廳的**聯絡簿**（成果帳本）。

| 系統 | 職員證 | 路徑 | 和誰連結 |
|---|---|---|---|
| 🗂️ 成績調閱室 | grade | `/grade`、學生 `/s/<代碼>` | 收所有系統的成績（倉庫） |
| 🕵️ 謎案課堂 CaseClass | cc | `/caseclass`、學生 `/cc/<代碼>`、投影 `/caseclass/live/<任務>` | → 成績調閱室、→ 英勇學院（完成度） |
| ⚔️ 英勇學院 ValorClass | game | `/valor`、學生 `/v/<代碼>` | ← 謎案課堂、→ 成績調閱室 |
| 📝 線上檢定所 | exam | 在事務所（Firebase） | → 成績調閱室（只連這個） |

- 大廳在 `/`（品牌、四棟建築介紹、申請職員證、我的職員證）；舊網址自動轉過去。
- **兩條規則讓「任意組合」不用逐一寫**：① 每個系統只檢查自己那張證 ② 帳本一律寫、讀別人的資料才看證。
- **共用地基**（不屬於任何一個系統）：老師帳號、學期、🏫 班級名單庫（含 🔀 跑班名單）、學生帳號；有任何一張證就能用。
- **📒 成果帳本 `grade_ledger`**：每個系統把「算好的結果」寫進來（source＝cc／game／exam），成績調閱室用 **🔗 帶入欄**拿；系統之間不直接讀對方的表。新系統只要會讀寫帳本，其他系統不用改。
- 停用某系統：資料保留但隱藏，重新開通就恢復；協同老師也要有那張證。
- 沒有某張證時，同步程式**不動、也不斷開**和那個系統的連結（不然重新開通後連結就不見了）；畫面說明原因＋「你可以使用：」列出有證的系統。
- 老師頁上方系統切換、學生頁右上角切換：只顯示有開通（學生：而且有被加入）的系統，多一顆「🏘️ 小鎮」回大廳。

### 4-F 兩個資料庫怎麼溝通

- 課堂小鎮伺服器用 **Firebase 服務帳戶**讀會員中心（`staff/*`、`staffpre/*`）確認職員證，寫進 `teachers.apps`／`active`；RLS 只看這兩個欄位（每次打開頁面查一次）。不用裝 firebase-admin：服務帳戶私鑰自己簽 JWT 換通行證，REST 讀寫。
- 會員中心連不上時：已開通過的照常用、沒開通過的不放行。
- 線上檢定所 → 成績調閱室：成績調閱室的伺服器去 Firebase 讀這位老師（同一個 Google 帳號 Email）**已公布**的測驗成績，寫進帳本。
- 會員中心 → 課堂小鎮伺服器：申請通知、使用統計都由網頁帶 Firebase ID token 呼叫課堂小鎮 API（伺服器驗證是誰）。
