# 🤝 合作方式、維護行事曆與文件地圖（完整版）

> 開發手冊的「字典」之一。開工必讀的是 [`HANDBOOK.md`](../HANDBOOK.md)（第 1、9 章是這裡的濃縮版）。

## 1. 和巫老師一起工作的方式

### 1-A 溝通

- 稱呼「**巫老師**」（不是吳老師）；繁體中文、親切、白話；技術概念用**小學生聽得懂的比喻**（例：Vercel＝店面＋廚房、Supabase＝倉庫、GitHub＝食譜保險箱；職員證、成果帳本＝小鎮的聯絡簿）。
- 回覆先講結論，再講細節；做完的事用條列，**不要貼程式碼給老師看**。
- 給選擇時：**2～3 個方案＋截圖＋我的建議**，老師常用「選 A」「回覆 1、2」快速決定。
- 需要老師貼到後台的東西（Firebase 規則、Supabase SQL）：**在對話裡直接給完整全文**方便複製，不要只給檔案路徑。
- 老師問「會不會…」「是不是…」時，先查證再回答（網路搜尋、讀程式），不確定就說不確定；說錯了要明確更正。
- 老師的名字一律寫「**巫魚子**」；不寫本名。

### 1-B 規劃與規格書

- **先規劃、後開工**：大系統先寫規格書，老師說「開發」「開工」才動手（曾經跳過規劃直接做，被糾正）。
- **一個系統只有一份規格書**（2026-11-04 老師強調）：不要另外留「規劃書」「草稿」，兩份會在開發時被讀錯。合併時逐條比對對話紀錄，舊的刪掉。
- 規格書裡把「**老師確認過的決定**」和「**Claude 的提案**」分開寫；設計複雜時，**每次修改都對照對話紀錄再檢查一次**（老師已經回答過的問題又被問一次＝規格書漏了）。
- 數字類規則（計分、倒扣、機率、期限）寫成白紙黑字並複述確認。
- 規格書放 Claude 專案文件（`claude/〇〇_開發規格書.md`）；開發中依規格書推進、每階段結束更新規格書。

### 1-C 分階段

- 老師喜歡「**先做可用的輕量版 → 試用 → 下一階段**」；每階段結束回報，**等老師說繼續**（有時老師會直接說「做完直接進下一階段」）。
- 老師會在課堂實際使用後回來調整；調整來時，**先處理老師列的問題，再處理新功能**。
- 老師有 token（用量）預算：大工程前先說預估規模；老師說「先討論、明天再做」就把討論結果寫進規格書，下次直接開工。
- 不確定的小細節：**先用合理預設做出來，交付時列出「我先這樣做了，請老師確認」**，不要卡住等回答。

### 1-D 每次交付時老師會看的東西

- 做了什麼（條列、用老師的話）。
- **老師要親手做的事**（貼 SQL、設環境變數、Redeploy、打開管理頁一次…）用 ⚠️ 標出來，完成前不能說「已上線」。
- 測試步驟（第一步、第二步…）＋「請老師特別看哪裡直不直覺」。
- 網站多久會更新（GitHub Pages、Vercel 約 2～5 分鐘）、看不到就 `Ctrl+Shift+R`。
- 結尾：文件已更新（✅ 已更新開發手冊／經驗庫）、本機資料夾已同步（或請老師雙擊 `sync-now.bat`）。

### 1-E 固定規矩（不用每次問）

- 學生頁**絕不**連回事務所首頁；分享給其他老師的系統與會員中心也不連回首頁（改連會員中心）。
- 事務所首頁改版先放 `index-preview.html`，老師說「**上線**」才換 `index.html`。
- 金鑰、密碼不進 repo（wuyutzu-tools 是公開 repo）；文件只記「哪個帳號登入哪裡」，不記密碼。
- 每次開發結束：更新 CHANGELOG、DEVELOPMENT、本手冊（第 7-D 收尾清單），並同步老師電腦的本機資料夾。
- 欄／列用 Excel 的意思：**欄＝直的、列＝橫的**；畫面文字要寫到不會誤會（必要時加「〔直的〕〔橫的〕」）。教室座位另有慣例：**排＝直的**（講台→布告欄方向）、**列＝橫的**，編號用**講台（老師）視角**（第 1 排在老師左手邊、第 1 列最靠講台），並在畫面上提醒一次。

## 10. 維護行事曆與待辦

### 10-A 定期要做的事

| 什麼時候 | 做什麼 |
|---|---|
| 每次開發結束 | 7-D 收尾清單（含本機資料夾同步） |
| 每週一早上 | 看「🔋 Firebase 資源報告」議題（自動）、會員中心「📊 使用狀況」燈號；🟡／🔴 就做健檢 |
| 有老師申請時 | 收到 Resend 通知信 → 會員中心審核；耗資源的系統（AI、地圖、即時連線）個別評估 |
| 每新增 3 個系統（或任何即時連線系統） | 全站連線健檢 `tools/health/check.py`，結果記在 DEVELOPMENT.md |
| 每學期開學前一週 | 全站健檢；確認 Supabase 專案都沒被暫停、cron-job.org 保活還在（課堂小鎮 `/api/health`、科普閱讀測驗 `/api/assignments`）；清掉不用的題庫、活動、測試資料；開新學期 |
| 收到供應商政策信（Google、Supabase、Firebase、Gemini） | 看一次內容，對照各系統程式有沒有用到；結果記進本手冊第 6 章 |
| 調校或學校信箱可能停用前 | 科普閱讀測驗的 Supabase 帳號搬到個人信箱（做法在「後台帳號清單」） |
| 系統變多、開發量變大時 | 改用 GitHub Desktop 管理本機資料夾；考慮自動同步 |
